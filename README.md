# TrailDCA

토스증권 OpenAPI + 구글 스프레드시트로 돌아가는 DCA / 트레일링 익절 자동매매 봇.

**기본값은 dry-run(모의투자)입니다.** `.env`의 `LIVE_TRADING=true`로 바꾸기 전까지는 실제 주문이 절대 나가지 않습니다.

## 1. 설치

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

## 2. Toss Securities OpenAPI 설정

1. 토스증권 WTS(영업점) 설정에서 Open API `client_id`/`client_secret` 발급.
2. **접근 허용 IP 등록 필수.** 이 봇을 실행하는 PC/서버의 공인 IP를 WTS Open API IP 화이트리스트에 등록해야 호출이 성공합니다. 배포 위치(로컬 PC ↔ 서버)를 바꾸면 IP도 다시 등록해야 합니다.
3. `.env`에 `TOSS_CLIENT_ID`, `TOSS_CLIENT_SECRET` 입력.
4. 계좌가 여러 개면 `TOSS_ACCOUNT_SEQ`를 지정하세요. 비워두면 `GET /api/v1/accounts` 응답의 첫 번째 계좌를 사용합니다.

## 3. 구글 스프레드시트 서비스 계정 설정

사람 로그인 없이 백그라운드에서 상시 접근하려면 서비스 계정이 필요합니다.

1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트 생성 (또는 기존 프로젝트 사용).
2. **API 및 서비스 → 라이브러리**에서 "Google Sheets API" 검색 후 사용 설정.
3. **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → 서비스 계정** 생성.
4. 생성된 서비스 계정 → **키** 탭 → **키 추가 → 새 키 만들기 → JSON** 다운로드.
5. 다운로드한 JSON 파일을 프로젝트 루트에 `service_account.json`으로 저장 (이미 `.gitignore`에 포함되어 커밋되지 않음).
6. JSON 파일 안의 `client_email` 값(예: `xxx@yyy.iam.gserviceaccount.com`)을 복사.
7. 대상 스프레드시트를 열어 **공유** → 위 `client_email`을 **편집자**로 추가.
8. `.env`의 `GOOGLE_SHEET_ID`는 이미 시트 URL에서 추출되어 기본값으로 채워져 있습니다:
   `1OP20AeVjn8g6WIB65uLB49reioEHOnnjff9sa3q0TQw`
9. 시트 탭 이름이 "Sheet1"이 아니면 `GOOGLE_SHEET_TAB`을 수정하세요. 헤더 행은 새 시트에만 자동으로 생성됩니다 (`종목코드, 종목명, 마켓구분, 보유수량, 매입금액_원화, 수익률, 전략적용여부, 최고수익률, 익절기준, 매도단계, 청산여부, 마지막갱신`). 이미 사용 중인 시트에 `매도단계` 컬럼이 없다면 헤더 행을 자동으로 고쳐쓰지 않으므로(`_ensure_header`가 경고만 남기고 건드리지 않음) **직접 `매도단계` 열을 `익절기준`과 `청산여부` 사이에 추가**해야 합니다.

## 4. 실행

```
python -m src.main
```

- 매일 KST 08:00 이후 최초 1회: 보유 종목을 조회해 시트와 동기화(신규 종목은 기본값으로 추가).
- 그 중 **매주 월요일**의 08:00 동기화에는 추가로 `청산여부=TRUE`인 행을 시트에서 완전히 삭제하는 정리 작업이 붙습니다 — 청산된 종목이 계속 쌓여 시트가 무한정 길어지는 것을 막기 위함입니다.
- 정규장 시간(한국 09:00-15:30, 미국 22:30-05:00경, 서머타임에 따라 변동) 동안 1초마다 수익률/최고수익률/익절기준을 갱신합니다.
- `전략적용여부`만은 별도로 `STRATEGY_ENABLED_REFRESH_INTERVAL_SECONDS`(기본 60초, `src/config.py`)마다 시트에서 다시 읽어옵니다 — 나머지 컬럼(보유수량/최고수익률/익절기준/매도단계 등)은 위 08:00 전체 동기화 때까지 그대로 두고, `전략적용여부` 값만 덮어씁니다. 시트에서 이 값을 수동으로 켜거나 끄면 최대 1분 안에 반영됩니다.
- 실제 매수/매도 **주문**은 장 시작 즉시가 아니라 시장·방향별로 정해진 지연 시간이 지나야 나갑니다 (`src/config.py`의 `KR_BUY_DELAY_AFTER_OPEN`/`US_BUY_DELAY_AFTER_OPEN`=1시간, `KR_SELL_DELAY_AFTER_OPEN`/`US_SELL_DELAY_AFTER_OPEN`=35분 -- 한국/미국 동일). 지연 중에도 최고수익률/익절기준 계산 자체는 계속 진행되므로, 지연이 끝나는 시점엔 이미 정확한 값을 갖고 있습니다.
- 이 지연 판단은 로컬 PC 시계가 아니라, Toss API 응답의 `Date` 헤더로 보정한 시각(`TossClient.now()`)을 기준으로 합니다 — PC 시계가 실제와 몇 초/몇 분 어긋나 있어도 장 시작 후 경과 시간 계산에는 영향이 없습니다.
- 시트 쓰기는 매 틱마다 나가지 않고 `SHEET_FLUSH_INTERVAL_SECONDS`(기본 1초, `src/config.py`)마다 그 사이 누적된 변경분을 모아 한 번에 씁니다 — Google Sheets API의 분당 쓰기 요청 한도를 넘기지 않기 위함입니다. 값을 늘리면(예: 5초) 요청 빈도가 더 줄어듭니다.
- 로그는 콘솔과 `traildca.log`에 동시에 남습니다.
- `Ctrl+C`(SIGINT)로 안전하게 종료됩니다 (진행 중인 주문 폴링을 마무리한 뒤 종료, 아직 시트에 못 쓴 변경분도 종료 직전 한 번 더 flush).

### 전략 요약 (`src/config.py`, `src/strategy.py`)

- **DCA 매수**: 종목당 누적 매입금액이 10만원(`DAILY_BUY_TARGET_KRW`) 미만이면 수익률과 무관하게 매일 5,000원(`DAILY_BUY_KRW`)씩 매수. 10만원 이상이면 수익률이 10%(`DAILY_BUY_RESUME_RATE`) 이상일 때만 계속 매수.
- **최고수익률(peak) 추적**: `max(peak, 종가기준수익률)`로 절대 내려가지 않게 갱신되지만, **이 갱신 자체는 틱마다가 아니라 하루 1번만** 일어납니다(`allow_peak_update` 플래그, `src/strategy.py`) — 매일 `daily_snapshot()`이 도는 KST 08:00 즈음(또는 서비스 재시작 시)에, 각 보유종목의 **가장 최근에 완전히 마감된 거래일 종가**를 `GET /api/v1/candles`(`interval=1d`)로 직접 조회해서(`main._closing_rate`) 그 종가 기준 수익률로 딱 한 번만 최고수익률을 계산합니다. 장중에 서비스를 새로 띄운 경우에도 `/api/v1/candles`가 반환하는 최신 봉이 "아직 마감 안 된 오늘 진행 중인 봉"이면 이를 건너뛰고 그 전날(진짜로 마감된) 종가를 씁니다 — 즉 언제 재시작하든 항상 확정된 전일종가만 반영됩니다. 그 이후 장중 매 틱에는 최고수익률 값 자체는 그대로 고정된 채로 있습니다. 다만 **하락률 판단(단계별 매도 발동 여부)은 여전히 매 틱 실시간으로** 그 시점에 고정돼 있는 최고수익률 대비 실시간 현재수익률을 비교해서 이뤄지므로, 장중에도 급락 시 단계별 매도는 정상적으로 발동합니다 — 달라지는 건 "최고수익률이 언제 올라가는지"뿐입니다. 아래에서 설명하는 크로싱/재활성화 리셋들은 이 하루-1회 제약과 무관하게 **그 즉시(실시간, 그날의 실시간 수익률 기준)** 발동합니다.
  - **누적 매입금액이 10만원(`DAILY_BUY_TARGET_KRW`) 미만이면서 아직 한 번도 매도단계가 발동한 적 없는(`매도단계=0`) 종목**: 최고수익률은 평소처럼(단, 하루 1번) 계속 갱신되지만, 청산 자체가 불가능하므로(아래 참고) 어떤 매도도 발동되지 않습니다.
  - **누적 매입금액이 10만원을 처음 넘기는 틱(역시 `매도단계=0`일 때만)**: 그 시점까지 쌓인 최고수익률을 버리고, 그 순간의 현재 수익률로 최고수익률을 다시 시작합니다. 이 리셋은 그날의 DCA 매수(`_attempt_daily_buy`/`_attempt_fallback_share_buy`) **자체가** 10만원을 막 넘긴 경우에도 그 매수 직후에 바로 발동됩니다(`_reset_peak_if_target_just_crossed`) — 이걸 안 하면, 매수 이전 틱에서는 아직 10만원 미만이라 매도 게이트가 걸려 있었고 매수 이후 틱에서는 이미 10만원을 넘긴 상태라 "방금 넘겼다"는 걸 감지할 틱이 아예 없어서, 매도가 원래 불가능했던 기간에 배경에서만 갱신되던 오래된(높은) 최고수익률이 리셋 없이 그대로 살아남아 매수 직후 곧바로 단계별 매도가 발동될 수 있었습니다.
  - **`매도단계`가 한 번이라도 0을 벗어난(즉 부분매도가 최소 1회 발동한) 종목은 위 두 게이트가 더 이상 적용되지 않습니다.** 부분매도는 `liquidate_partial`이 매입금액도 판 수량에 비례해서 함께 줄이기 때문에, 매도 이후 누적 매입금액이 다시 10만원 밑으로 떨어지는 경우가 흔합니다. 이 경우에도 최고수익률 추적·하락률 판단·추가 매도(부분/전량)가 계속 정상적으로 이어집니다 — 10만원 미만이라고 해서 "아직 포지션을 쌓는 중"으로 취급해 매도단계 기억을 지우거나 익절 로직을 다시 잠그지 않습니다. (반대로 DCA 매수는 이 조건과 무관하게 계속 10만원 미만 규칙을 따르므로, 부분매도로 비중을 줄인 종목이 다시 5,000원씩 매수되면서 동시에 추가 단계 매도 대상이 될 수도 있습니다.)
  - **`전략적용여부=FALSE`인 동안**: `수익률`은 계속 실시간으로 갱신되고(실계좌 미러링과 같은 취지) `최고수익률`도 하루 1번의 종가 기준 갱신은 그대로 받지만, `익절기준`/`매도단계`와 매수·매도 판단 자체는 멈춥니다.
  - **`전략적용여부`가 `FALSE`에서 `TRUE`로 바뀐 바로 그 틱**: 비활성화되어 있던 동안 쌓인 최고수익률을 버리고, 그 순간의 현재 수익률로 최고수익률·익절기준·매도단계를 전부 새로 시작합니다(10만원을 막 넘긴 틱과 동일한 리셋 로직) — 관리가 꺼져 있는 사이 조용히 올라간 고점 때문에 다시 켜자마자 곧바로 매도가 발동되는 것을 막기 위함입니다.
  - **봇 밖에서(예: 토스증권 앱/MTS로 수동) 매수가 일어나 보유수량이 늘어난 경우**: 이 봇이 직접 실행한 매수·매도는 항상 그 즉시 `보유수량`을 갱신하므로, 매 틱 실계좌 조회 결과와 직전에 기록해 둔 `보유수량`이 달라져 있으면(늘어난 경우만) 그건 이 봇이 모르는 외부 매수로 판단합니다(`process_symbol`의 `external_buy_detected`). 이 경우 위의 어떤 게이트(누적 매입금액 10만원 미만 여부, 매도단계가 이미 0을 벗어났는지)와도 무관하게 **최고수익률을 그 틱의 현재 수익률로 즉시 재설정**하고, **매도단계를 0으로 초기화**하며, **익절기준을 새 최고수익률 기준으로 재계산**합니다(`src/strategy.py`의 `update_peak_threshold_and_sell_stage_gated`, `external_buy_detected` 파라미터) — 이 틱에는 최고수익률이 방금 현재 수익률로 리셋된 직후라 하락폭이 0%이므로 어떤 매도(부분/전량)도 발동되지 않습니다. 외부 매수로 평단가가 오르며 수익률이 갑자기 뚝 떨어지는 경우, 예전(더 높았던) 최고수익률 대비 하락폭이 커 보여 실제로는 하락이 아닌데도 즉시 익절이 발동해버리는 걸 막기 위한 안전장치입니다. **다만 이 매수 이전에 최고수익률이 이미 10%(`PEAK_ACTIVATION_RATE`) 이상으로 익절 로직이 활성화돼 있었다면**, 외부 매수로 희석된 새 최고수익률 자체가 10% 밑으로 떨어지더라도 활성 상태는 그대로 유지됩니다 — 그렇지 않으면 큰 외부 매수 한 번으로 이미 추적 중이던 익절 보호가 조용히 꺼져버릴 수 있기 때문입니다. 같은 틱에 **`직전매수수익률`도 이 실제 현재 수익률로 함께 리셋**됩니다(`src/main.py`, `process_symbol`) — 이 값은 원래 이 봇 자신의 매수(금액 주문이든 1주 폴백이든)에서만 갱신되지만, 외부 매수로 실제 상황이 이미 바뀌었으니 매수 전에 남아있던 오래된 래칫 기준이 다음 폴백 매수 판단을 잘못 막거나 잘못 통과시키지 않도록 함께 초기화합니다.
- **청산(고점 대비 하락률 기반 단계별 매도)**: 최고수익률이 10%(`PEAK_ACTIVATION_RATE`) 이상 활성화된 이후, **최고수익률 대비 상대적으로 몇 % 하락했는지**를 기준으로 3단계에 걸쳐 매도합니다 (`src/strategy.py`의 `update_peak_threshold_and_sell_stage_gated`):
  - 고점 대비 **30%**(`LIQUIDATION_STAGE_1_DRAWDOWN`) 하락: 그 시점 보유수량의 **50%**(`LIQUIDATION_STAGE_SELL_FRACTION`) 매도.
  - 고점 대비 **40%**(`LIQUIDATION_STAGE_2_DRAWDOWN`) 하락: 남은 보유수량의 50% 추가 매도 (최초 보유수량의 25%만 남음).
  - 고점 대비 **50%**(`LIQUIDATION_STAGE_3_DRAWDOWN`) 하락: 남은 전량 매도, `청산여부=TRUE`.
  - 하락률은 **상대 비율**로 계산합니다: `현재수익률 ≤ 최고수익률 × (1 - 하락률)`. 예를 들어 최고수익률이 30%였다면 30% 하락 트리거는 현재수익률 21% 이하, 40% 하락은 18% 이하, 50% 하락은 15% 이하에서 발동됩니다.
  - **틱당 최대 1개 단계만 발동**합니다. 급락으로 한 틱에 여러 단계 조건을 동시에 만족해도(예: 30% 단계가 아직 발동 전인데 바로 45% 하락) 아직 발동되지 않은 것 중 **가장 얕은(이른) 단계**만 이번 틱에 발동하고, 하락률이 유지된다면 다음 틱에 그 다음 단계가 이어서 발동됩니다 — 즉 30% → 40% → 50%를 (하락 폭이 충분하면) 순서대로 거치며, 중간 단계를 건너뛰고 곧바로 더 깊은 단계로 넘어가지 않습니다.
  - 각 단계는 종목당 평생 한 번씩이 아니라, **최고수익률이 그 이후 더 갱신되어 새로운 고점을 찍으면 그 새 고점을 기준으로 30%/40%/50% 하락 감시가 처음부터 다시 시작**됩니다 — 부분매도 이후 반등해서 신고점을 찍으면, 그 신고점에서 또 하락할 때 다시 단계별 매도가 발동될 수 있습니다.
  - **최고수익률 구간별로 적용되는 단계가 다릅니다** (`LIQUIDATION_STAGE_1_MIN_PEAK`/`LIQUIDATION_STAGE_2_MIN_PEAK`) — 고점이 낮았던 포지션은 굳이 얕은 하락에 반응하지 않고 마지막 안전장치(50% 하락 전량 매도)만 적용됩니다:
    - 최고수익률 < 20%: 50% 하락(전량 매도) 단계만 적용. 30%/40% 하락 단계는 아예 발동하지 않습니다.
    - 20% ≤ 최고수익률 < 30%: 40%/50% 하락 단계만 적용 (30% 하락 단계는 건너뜀).
    - 최고수익률 ≥ 30%: 30%/40%/50% 하락 세 단계 모두 적용.
    - 어떤 단계가 건너뛰어지면(예: 최고수익률 25%에서 곧바로 40% 하락) "틱당 1단계" 규칙은 그 종목에 실제로 적용 가능한 단계들 사이에서만 순서를 지킵니다 — 30% 단계가 애초에 적용 대상이 아니면 40% 단계가 그 자리에서 바로 발동됩니다.
  - 시트의 `매도단계` 컬럼(0/1/2)이 이 진행 상태를 저장하며, 새 고점이 찍히는 순간 자동으로 0으로 리셋됩니다.
  - 누적 매입금액이 10만원(`DAILY_BUY_TARGET_KRW`) 미만이면 이 단계별 매도 자체가 전부 생략됩니다 — 아직 DCA 목표 금액을 다 채우지 못한 포지션을 일시적인 하락으로 정리하지 않기 위함이며, 포지션이 다 갖춰진 뒤에야 청산이 가능해집니다.
  - 국내장(KR)은 소수점 매도가 안 되므로 부분매도 수량은 정수(내림)로 계산됩니다. 내림 결과가 0주가 되는(보유수량이 너무 적은) 경우 그 단계는 건너뛰고 다음(더 깊은) 단계에서 다시 시도합니다. 해외장(US) 소수점 매도는 정수로 내리진 않지만, Toss API가 주문 수량을 **소수점 6자리까지만** 허용하므로 `보유수량 × 매도비율` 계산 결과를 소수점 6자리에서 내림 처리합니다(`_partial_sell_quantity`, `PARTIAL_SELL_MAX_DECIMALS`) — 그대로 보내면 "소수점 수량은 소수점 6자리까지 지원합니다" 오류로 주문이 거부됩니다.
  - **익절기준** 컬럼은 별도 공식이 아니라 **바로 이 단계별 매도 상태에서 그대로 파생**됩니다(`src/strategy.py`의 `next_liquidation_trigger_rate`) — "아직 발동 안 된 것 중 가장 얕은, 그리고 현재 최고수익률 구간에서 실제로 적용 가능한 단계가 발동되는 수익률"을 보여줍니다: 매도단계=0이고 최고수익률 ≥ 30%면 `× (1-30%)`, 최고수익률이 20~30% 구간이라 30% 단계가 적용 안 되면 `× (1-40%)`부터, 최고수익률 < 20%면 `× (1-50%)`만 보여줍니다. 즉 익절기준은 이제 청산 여부를 결정하는 별도 기준이 아니라 위 단계별 매도의 "다음 실제 트리거 지점"을 숫자로 보여주는 값이며, 소수점 매수 미지원 종목의 폴백 매수 진입 기준(아래 참고)에도 이 값이 그대로 쓰입니다.
- **소수점 매수 미지원 종목**: 5,000원 금액 주문이 실패하면 1주 통매수로 폴백합니다. "1주를 추가로 샀을 때 예상되는 수익률"(매수 *후* 평단가가 밀리면서 낮아질 값, `projected_rate`)을 기준으로 매입금액 구간별로 다르게 판단합니다:
  - **현재 매입금액 < 10만원 & 예상 누적 매입금액 < 13만원 (`DAILY_BUY_TARGET_KRW`/`NONFRACTIONAL_DCA_CEILING_KRW`)**: DCA 유예구간 — 수익률과 무관하게 무조건 매수 (소수점 지원 종목의 "10만원 미만 무조건 매수"와 같은 취지 — 1주 단위라 10만원을 한 번에 넘길 수 있어 여유분(13만원)을 둠). 이 구간의 매수는 최고수익률을 리셋하지 않습니다 — 수익률 게이팅 없이 강제로 사는 날마다 그날의 (자칫 낮을 수 있는) 수익률로 최고수익률을 덮어쓰면, 아직 다 쌓이지도 않은 포지션의 트레일링 스탑 추적이 매일 망가지기 때문입니다.
  - **현재 매입금액 < 10만원 & 예상 누적 매입금액 ≥ 13만원**: `projected_rate ≥ 10%(PEAK_ACTIVATION_RATE)`이면 진입 — 익절기준이 10%보다 높게 올라가 있어도 이 구간에서는 그 높은 기준을 요구하지 않습니다.
  - **현재 매입금액 ≥ 10만원**: `projected_rate ≥ max(10%, 직전 매수 체결 후 실제 수익률 + 3%(`NONFRACTIONAL_ENTRY_RATCHET_STEP`))`이어야 진입 — **래칫(ratchet) 방식**입니다. 같은 종목에 이 폴백 매수가 연속으로 들어가려면, 매번 직전 매수(금액 주문이든 1주 폴백이든, 이 봇이 체결시킨 가장 최근 매수)가 실제로 체결된 뒤의 수익률보다 최소 3%p 더 높아야만 통과됩니다(포지션이 정체되거나 계속 나빠지는 동안엔 추가 매수를 막고, 실제로 개선되고 있을 때만 통과시키는 구조). `+3%`는 **직전 매수 값에만** 더해지고 `10%` 플로어에는 더해지지 않으므로, 직전 매수의 실제 체결 수익률이 7% 미만이면(한 번도 매수한 적 없어 0%인 경우 포함) `max(10%, 7% 미만+3%)`가 그대로 `10%`가 되어 플랫 10% 기준으로 돌아갑니다. 직전 값이 7~10% 사이면 그 사이 어딘가(예: 8% → 11%)로, 10% 이상이면 항상 `직전값+3%`로 계속 올라갑니다(`strategy.nonfractional_entry_allowed`). 단, 진입 여부를 가르는 이 비교 자체는 여전히 이번 1주 폴백 매수의 (매수 *전에* 계산한) `projected_rate`를 씁니다 — 아래 문단에서 설명하는 건 이 래칫 기준값(`직전매수수익률`) 자체가 매수 *후에* 어떤 값으로 갱신되는지입니다.

  **직전매수수익률** 컬럼(시트)은 이 봇이 실행한 매수가 체결될 때마다 — 금액(소수점) 주문이 성공하든, 1주 폴백 매수가 체결되든 — 그 매수의 **실제 체결 후 수익률**(`row.profit_rate`, 즉 Toss API가 돌려주는 진짜 `profitLoss.rate`)로 갱신됩니다. 폴백 매수의 경우 진입 여부는 매수 *전* `projected_rate`로 판단하지만, 값을 저장할 때는 매수 *후* 실제 체결가 기준 수익률을 쓴다는 점에 유의하세요 — 시세가 움직여 예상치와 실제 체결 결과가 다를 수 있으므로, 다음 번 래칫 비교는 항상 실제로 어디에 정착했는지를 기준으로 삼습니다. 그 외에는 최고수익률처럼 전용 리셋 로직 없이 이 값 하나만 그대로 유지됩니다. **셀이 공백인 경우**(이 봇으로 매수한 적이 한 번도 없는 종목, 또는 컬럼 추가 이전부터 있던 기존 행)에는 0%가 아니라 그 행의 **최고수익률**로 대체해서 씁니다(`SheetRow.from_record`) — 0%로 취급하면 이미 수익이 많이 난 포지션도 플랫 10% 기준으로 잘못 강등되기 때문입니다. 새로 발견된 종목을 시트에 추가할 때도(`SheetsClient._default_row_values`) 이 컬럼을 명시하지 않으면 같은 이유로 최고수익률 값을 그대로 복사해 씁니다.

  **DCA 유예구간 밖에서 체결된 폴백 매수**는 최고수익률을 이 매수의 `projected_rate`로 **무조건 덮어씁니다**(직전 최고수익률과 비교하지 않고 그대로 교체) — 1주를 추가로 사면서 평단가가 밀려 수익률이 낮아졌으니, 최고수익률도 그 하락을 반영해야 트레일링 스탑이 인위적으로 왜곡되지 않기 때문입니다. **익절기준도 같이 재계산**됩니다: 새 최고수익률이 10% 이상이면 그 종목의 **현재 매도단계**를 기준으로 `next_liquidation_trigger_rate(새 최고수익률, 현재 매도단계)`를, 10% 미만이면 `-100%`(inert)를 씁니다 — 매도단계 자체는 이 리셋으로 초기화되지 않습니다. **유예구간 안에서 체결된 매수는 최고수익률/익절기준을 건드리지 않습니다** — 아직 포지션이 다 안 쌓인 초기 단계라, 수익률 게이팅 없이 강제로 사는 날마다 그날의 (자칫 낮을 수 있는) 수익률로 최고수익률을 덮어쓰면 트레일링 스탑 추적이 매일 망가지기 때문입니다.

  이 매수로 매입금액이 10만원을 막 넘기는 경우엔, 위 로직이 이미 최고수익률/익절기준을 세팅한 뒤에 `_reset_peak_if_target_just_crossed`가 한 번 더 그 순간의 **실제** 수익률(`projected_rate`가 아닌 체결 후 실제 수익률)로 최고수익률·익절기준·매도단계를 재차 리셋합니다(위 크로싱 리셋과 동일 로직) — 크로싱 리셋이 나중에 실행되어 최종 값을 결정합니다.

  이 기능은 시트에 `직전매수수익률` 컬럼이 있어야 동작합니다(`수익률`과 `최고수익률` 사이). `_ensure_header()`는 헤더가 `SHEET_COLUMNS`와 다르면 자동으로 고치지 않고 경고만 남기며, `read_rows()`는 `get_all_records(expected_headers=...)`가 이 컬럼을 찾지 못하면 예외를 던지도록 돼 있어(gspread 6.x 기준 — 데이터가 잘못된 컬럼에 섞여 들어가는 게 아니라 그냥 실패), 실제 시트에도 이 컬럼을 미리 삽입해 뒀습니다.

  이 전략이 관리하는 종목은 이미 포지션이 있다는 전제이며, 최초 진입(첫 매수)은 수동으로 하는 것을 가정합니다.

### 시트 ↔ 실계좌 정합성 (MTS 등으로 수동 거래하는 경우)

봇을 거치지 않고 MTS 앱 등에서 직접 매도/매수하면 시트가 실계좌와 어긋날 수 있는데, 이를 자동으로 맞춰주는 로직이 있습니다 (`process_symbol`, 매 틱 실시간 반영):

- **수동 매도 감지**: `청산여부=FALSE`인데 실계좌 조회 결과 더 이상 그 종목을 보유하고 있지 않으면(그리고 시트에 남아있던 보유수량이 0보다 크면), 봇이 직접 청산한 게 아니어도 보유수량/매입금액/평가금액/평가손익을 0으로, `청산여부`를 `TRUE`로 자동 정리합니다. 그래야 낡은 매입금액 기준으로 봇이 재매수를 시도하는 걸 막을 수 있습니다. (시트에 사람이 미리 추가만 해두고 아직 한 번도 매수 안 한 행은 보유수량이 원래 0이라 이 로직에 안 걸리고 그대로 둡니다.)
- **수동 재매수 감지**: `청산여부=TRUE`인데 실계좌 조회 결과 다시 그 종목을 보유하고 있으면, `청산여부`를 `FALSE`로 되돌리고 보유수량/매입금액 등을 실제 값으로 갱신하며, **최고수익률/익절기준/매도단계를 현재 수익률 기준으로 새로 시드**합니다(청산 직전의 낡은 값을 이어받지 않음, 매도단계는 0으로 리셋). 이 재시딩도 위 "누적 매입금액 10만원" 게이팅을 그대로 따릅니다 — 재진입 매입금액이 10만원 미만이면 최고수익률만 현재 수익률로 시작하고 익절기준은 -100%로 고정, 재진입 한 방에 10만원을 넘겼다면 그 자리에서 바로 정상 공식으로 활성화됩니다. 또한 그날 봇 자신의 DCA 매수는 건너뜁니다 — 사람이 방금 수기로 재진입했으므로 같은 거래일에 봇이 5,000원을 또 얹어 사지 않도록 "오늘 매수 완료"로 표시해둡니다.

⚠️ **참고**: 시트에서 `익절기준`/`최고수익률`/`매도단계` 셀을 사람이 직접 수정해도 대부분 효과가 없습니다. 시트는 하루 한 번(08:00 KST) 또는 서비스 재시작 시에만 다시 읽히고, 그마저도 최고수익률이 활성화된 종목은 매 틱 `peak`·`매도단계` 상태로 익절기준을 다시 계산해 덮어쓰고 매도단계도 그 시점 상태로 덮어씁니다. 매입금액이 10만원 미만인 종목은 사람이 `익절기준`에 어떤 값을 넣어놔도 다음 틱에 무조건 -100%로, `매도단계`는 0으로 다시 덮어써집니다. 청산 단계별 하락률/매도비율(그리고 그로부터 파생되는 익절기준)을 바꾸려면 `src/config.py`의 `LIQUIDATION_STAGE_*` 상수를 수정하세요.

### Dry-run → Live 전환

1. `LIVE_TRADING=false`(기본값) 상태로 최소 하루 이상 돌려보고, 로그와 시트에 찍히는 `[DRY-RUN] BUY/SELL` 판단이 의도한 규칙과 일치하는지 확인하세요.
2. 문제 없으면 `.env`에서 `LIVE_TRADING=true`로 변경 후 재시작. 코드 변경은 필요 없습니다.
3. **주의**: dry-run에서는 실제 주문을 넣지 않으므로, 종목별 소수점 거래 지원 여부에 따라 실제 매수가 5,000원어치 금액 주문으로 체결될지 1주 매수로 폴백될지는 라이브 전환 후에만 확인할 수 있습니다.

## 5. 상시 구동 관련

- 보유 종목에 미국 주식이 있으면 하루 최대 20시간 이상(한국장 09:00~15:30 + 미국장 22:30~05:00경) 프로세스가 떠 있어야 합니다.
- 이 프로젝트는 순수 Python 장기 실행 프로세스로 되어 있어 어디서나 `python -m src.main`으로 실행 가능합니다. OS 서비스 등록(Windows 작업 스케줄러의 "로그온 여부와 상관없이 실행" 옵션 + 절전 모드 해제, 또는 리눅스 systemd 등)은 배포 환경이 정해진 뒤 별도로 구성하세요.
- 크래시 시 자동 재시작이 필요하면 배포 환경에 맞는 프로세스 매니저(Task Scheduler 재시도, systemd `Restart=on-failure`, supervisord 등)를 추가로 구성하세요. 현재 코드는 재시작되어도 `state.json`과 시트의 값으로 상태를 복구합니다 (단, 재시작 당일 아직 매수를 시도하지 않았다면 다시 시도합니다 — Toss `clientOrderId` 멱등성 키로 중복 주문 자체는 방지됩니다).
